**Шаг 3: правила переноса (Архитектор и Босс, 09.10).**
1. **Перенос побайтный, без нового `'use strict'`.** Строгий режим для нестрогого кода — потом, отдельным коммитом на файл с полным прогоном.
   - Уточнение Фронта (сверено с кодом): большой блок `app.html` 1085 сам начинается с `'use strict';`, и весь его код сейчас строгий.
   - Поэтому файл, вырезанный из этого блока, первой строкой несёт ту же директиву `'use strict';`. Это одна строка, режим кода не меняется.
   - Без неё код стал бы нестрогим, а это и есть изменение поведения.
   - Файлы из нестрогих блоков директиву не получают. Например, `pwa-lock.js`: строгий режим у него внутри IIFE, как и было.
   - Проверка «split» в `scriptv` допускает эту строку только у кусков строгого блока и роняет тест при несовпадении режима.
2. **Порядок `<script src>` в точности как порядок блоков в исходном `app.html`.**
   - Классические скрипты делят одну глобальную область: `let`/`const` верхнего уровня видны только скриптам, подключённым после. Иначе TDZ/ReferenceError.
   - Куски большого блока режутся с конца по строкам и встают на его место подряд.
   - «split» собирает их обратно и сравнивает побайтно, так что другой порядок проверку не пройдёт.
3. **Ни один вынесенный файл не падает на загрузке.**
   - Проверка в `names.test.mjs`: слушатель `error` на window с именем файла `js/*`, на всех 16 загрузках.
   - Красный прогон: `NAMES_SWAP=<файл>` ставит его `<script src>` перед предыдущим `<script>`.
5. **Ошибка в одном файле больше не останавливает весь блок (Архитектор, 09.10).**
   - До разбиения исключение при загрузке обрывало весь блок 1085: ничего ниже не выполнялось, приложение не стартовало целиком.
   - После разбиения обрывается только этот файл. Его объявления ниже места ошибки не появятся. Следующие файлы грузятся и работают в полусломанном состоянии, ошибка может всплыть совсем в другом месте (пример: `content.js` упал → `renderThemeSeg`: `SHOP_THEMES is not defined`).
   - Поэтому в **каждой пачке** обязателен красный прогон проверки загрузки в `names`:
     - `NAMES_SWAP=<файл>` — порядок;
     - `NAMES_THROW=<файл>` — файл бросает исключение на первой строке.
     - Проверка «ни один `js/*` не падает на загрузке» должна покраснеть с именем файла и строкой.
6. **Подъём функций между файлами.**
   - Внутри одного блока код при загрузке может вызвать или взять функцию, объявленную ниже. Между файлами нельзя.
   - `scriptv` «split» ищет такие места статически (esprima, все ветки) до выноса.
   - Найдено: `reader-ui` (2359–2736 @ `ca8aa1b`), строка 2598 `el('btnBack').onclick=closeReader;` выполняется при загрузке. `closeReader` объявлена в 2739, это следующий кусок `session-summary`.
   - Уточнено после F: `session-summary` тоже нельзя вынести отдельно. Тогда `closeReader` окажется в файле после блока 1085, а строка 2598 блока выполняется раньше. Пробный вынос: `scriptv` 19/21, `names` 5/7, хвост блока после 2598 не выполнился. Откачено.
   - Значит, ни `reader-ui`, ни `session-summary` нельзя вынести отдельным файлом побайтно, нужно решение. Варианты:
     - (а) `reader-ui` и `session-summary` — один файл (2359–2905);
     - (б) перенести одну строку 2598 в `session-summary` — это уже правка кода, не перенос.
7. **Каждый файл — отдельный коммит.** Полный прогон на каждом коммите (для `git bisect`), счёт тестов пишется в сообщение коммита. `js/pdf.js` идёт отдельным пушем.

## 2. Предлагаемое разбиение (чистый рефакторинг)

Принцип 1а: **классические** скрипты `<script src>` на том же месте, где сейчас большой `<script>`, **непрерывные куски без перестановки кода**. `'use strict';` первой строкой только у кусков строгого блока 1085, режим сохраняется (см. раздел 0, «Шаг 3: правила переноса»).
Почему не ES-модули: глобальные функции нужны inline-обработчикам; top-level `const/let` классических скриптов общие между файлами (общая глобальная лексическая область), так что поведение остаётся тем же.

Риски:
- Подъём функций (hoisting) больше не работает между файлами: top-level код, который сразу вызывает функцию или читает `const` из более позднего файла, упадёт с ReferenceError/TDZ. Ловит шаг 0.
- Нет `?v=` у нового `<script src>` → старый кеш SW отдаёт старый файл к новой HTML (смесь сборок). Обязательно делать в шаге 1 и проверять в pwa-verify (a).
- Время запуска ≤ 3 с: +~13 запросов через SW (из кеша; гипотеза: единицы мс на запрос). Сравнить `run.res` журнала до/после, повторы reload N=50, CPU×6.
- Порядок: модуль выполняется после всех классических скриптов — сохраняется, если файлы синхронные (без `defer/async`) на прежнем месте.
- Ошибка/404 любого файла → `__rqStart` не определён → сработает сторож (экран ошибки), данные не трогаются.
- rqt: ничего зависимого от NS в разбиении нет; build-dist для rqt тоже должен копировать `js/`; каждую часть проверять на `/test/`.
- Свой IDB-помощник в 3422 (дубль storage/idb.js) в 1а не трогать — отметить на потом.
