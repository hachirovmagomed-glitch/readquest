# js/ — классические скрипты, вынесенные из app.html (этап 1а)

- Порядок и состав — `handoff/stage1a-split.md`. Каждый файл подключается `<script src="js/<имя>.js"></script>` на месте вырезанного куска, без `defer`/`async`.
- **Вынос побайтный.**
  - Файл — непрерывный кусок inline-блока по целым строкам, без перестановок.
  - Если блок начинается с `'use strict';` (большой блок 1085), файл первой строкой несёт ту же директиву, и режим не меняется. Больше ничего не добавляется.
  - У кусков нестрогих блоков директивы нет. `pwa-lock.js` — блок целиком, строгий режим у него внутри IIFE.
  - `test/scriptv.test.mjs` («split») собирает куски обратно (швы между кусками одного блока склеиваются) и сравнивает сборку с `SPLIT_BASE` (по умолчанию `1c5b7b9`) байт в байт.
- **Порядок `<script src>` = порядок кусков в исходном `app.html`.** Куски большого блока режутся с конца и стоят подряд на его месте. `let`/`const` верхнего уровня видны только скриптам после них. «split» другой порядок не пропустит, `names` (`NAMES_SWAP`) ловит падение файла на загрузке.
- **Правило 1 (Архитектор, 09.10): в `<script>` атрибут `src` всегда ПЕРВЫЙ** — `<script src="js/x.js" defer>`, не `<script defer src=…>`. Замена `?v=BUILD` в `build-dist.sh` ловит только `<script src="js/`. Иначе сборка падает на стороже («no-v»).
- **Правило 2 (Архитектор, 09.10): строки с путями внутри `js/*` не должны меняться.**
  - `build-dist.sh` применяет к `js/` только то правило, что было у inline-кода в HTML (`from './x.js'` → `?v=`).
  - Общий sed для модулей (`'./x.js'` → `?v=`) `js/` обходит.
  - Проверка — `scriptv` «split»: к каждому файлу дописывается `'./probe-x.js'`, он должен выйти из сборки как есть. Красный прогон: `SCRIPTV_BREAK=sedjs`.
  - При каждом выносе (шаг 3) прогонять `scriptv` обязательно.
- `build-dist.sh` копирует сюда только `*.js` (этот README в сборку не попадает) и дописывает `?v=BUILD` к каждому `<script src="js/…">`. Тот же `?v=BUILD` стоит в precache у SW. Сборка падает, если у локального `<script src>` нет `?v=<сборка>` или файла нет в dist.
- Проверки: `test/scriptv.test.mjs` (новые скрипты к новой HTML + «split»), `test/names.test.mjs` (имена из обработчиков и глобальные имена, которые объявляют файлы `js/`, находятся после загрузки).
