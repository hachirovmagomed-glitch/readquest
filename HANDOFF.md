## 1. Продукт

ReadQuest — читалка с геймификацией: читаешь свои книги и получаешь опыт, золото и награды.

**Откуда начали.** Прототип v6 — один HTML-файл примерно на 3600 строк (`source/v6.html`): библиотека, читалка, RPG-профиль, XP и стрики, квесты, магазин, цитаты, ачивки, поддержка PDF и FB2. Этот файл больше не правим, он остаётся как образец.

**Для кого.** Взрослые 20–35 лет, которые раньше много читали, а сейчас читают реже двух раз в неделю, и у которых есть хотя бы один свой файл книги.

**Главная метрика.** Сколько дней в неделю человек читает не меньше 10 минут. Цель: медиана ≥ 4 дней на второй неделе теста.
- Мягкий стрик засчитывается с 2 минут в день.
- Ежедневное задание и метрика засчитываются с 10 минут в день.

### MVP — 4 экрана

Рабочий файл приложения — `source/app.html`. Нижняя навигация: **Библиотека | Профиль**. Читалка и итог сессии вкладками не являются.

| Экран | Что на нём |
|---|---|
| Библиотека | «Продолжить», цель 10 минут, мягкий стрик, полка книг. Без RPG. |
| Читалка | Режим фокуса включён по умолчанию: никаких всплывающих XP и RPG. Таймера и кнопки ▶ нет: открыл книгу — минуты считаются. Внизу тонкая полоска прогресса дня (3 px), над ней справа номер страницы «34 / 210». Щипок двумя пальцами меняет размер шрифта (14–30), во время жеста видна плашка «Aa N», текст перестраивается один раз после отпускания. |
| Итог сессии | XP, стрик, прогресс ежедневки и недели. Строки «+30 🪙 ежедневка выполнена» / «+120 🪙 неделя выполнена», только если начислено этой сессией. Одна кнопка «В библиотеку». |
| Профиль | Рамка героя и кнопка-заглушка «Создать героя», статус ежедневки и недели (без кнопок «Забрать»), золото, шторка «Награды из жизни». |

### Экономика

- **Опыт (XP)** = 10 × засчитанные минуты, только за чтение. Считается из строки в `sessions[]`, по одному разу на сессию.
- **Золото** — только за задания:
  - ежедневка +30 🪙: день, в котором набралось 10 минут;
  - неделя +120 🪙: на 4-й засчитанный день недели пн–вс. 5-й день недельную награду второй раз не даёт.
- Награды начисляются **автоматически на экране итога сессии**, кнопки «Забрать» нет.
- Начисление идемпотентно: XP — по UUID сессии (`game.awardedSessionIds`), ежедневка — по дню (`game.dailyPaidDays`), неделя — по понедельнику недели (`game.weeklyPaidWeeks`). Повторный показ итога, перезагрузка или повторный импорт бэкапа второй раз не платят.
- **«Награды из жизни»** (например, «Кофе», «Серия сериала»): цены по уровням 100 / 250 / 500 🪙, своей цены нет. По умолчанию 3 слота, можно до 5.
- **Защита от забытой книги:** не больше 3 минут на одну страницу (настройка «Макс. время на страницу» = 3 мин по умолчанию). Фон и скрытая вкладка = 0.
  - Для PDF потолок может расти: если человек зумит или двигает страницу больше чем на 20 % экрана, к потолку этой страницы добавляется +1 минута, не чаще раза в минуту и не выше 8 минут. На новой странице снова 3 минуты.
- **День — локальный** (по часам телефона, не UTC). Сессия относится к дню, в который началась: чтение 23:50–00:15 — одна строка, все минуты идут в первый день.

### ИИ-герой — отложен

Сейчас есть только кнопка-заглушка «Создать героя». Она показывает «Скоро ✨» и записывает событие `hero_create_tapped`. Настоящий ИИ-портрет делаем, только если на неё нажмёт больше трети тестеров.

## 2. Данные

Подробно — в `source/STORAGE.md`. Схема `schemaVersion: 1`.

- **LocalStorage**, ключ `rq_v1`: `{ schemaVersion: 1, progress, game, library }`. Тела книг сюда не кладём. Настройки читалки — в ключе `rq_set`.
- **IndexedDB** `readquest` (версия 3), хранилища:
  - `files` — тела книг (`text:{id}`, `pdf:{id}`);
  - `sessions` — `sessions[]`;
  - `events` — события.
- **`sessions[]`** — только чтение, одна строка на сессию:
  `{ id: UUID, date: 'YYYY-MM-DD', bookId, minutes, pageTurns }`.
  `id` генерирует читалка (`crypto.randomUUID()`), а не автоинкремент базы. Старые строки без `id` получают детерминированный `legacy-…` id. Минуты считает только `reader-session.js` в конце сессии.
- **`events`** — `page_visible` с `pageVisibleMs` и аналитика (`hero_create_tapped`). В `sessions[]` они не попадают.
- **`game`**: `gold`, `awardedSessionIds`, `dailyPaidDays`, `weeklyPaidWeeks`, `rewardPurchases[{ id, title, price, at }]`, `anti: { minSec: 12, maxMin: 3 }`.
  Старые поля `dailyClaimed` / `weeklyClaimed` остались для совместимости: их один раз читает миграция, а новые сборки их больше не пишут.
- **Стрик** лежит в `progress.streak`, не в `game`.
- **Экспорт и импорт** — один JSON:
  `{ schemaVersion: 1, progress, game, library, sessions, events, settings? }`. Файлы PDF в него не входят. При импорте `sessions` и `events` заменяются целиком.
- Миграция со старого v6 (ключ `readquest`) в `rq_v1` выполняется один раз при запуске.
- Если приложение закрыли без «←», открытая сессия сохраняется черновиком (`rq_session_draft`) и записывается при следующем запуске.

```
README.md            — короткий указатель
HANDOFF.md           — этот файл
BOTS.md              — описания ботов команды для нового аккаунта
source/
  app.html           — рабочее MVP-приложение (точка входа)
  v6.html            — старый монолит, образец, не править
  reader-session.js  — учёт минут, сессий, черновиков (единственное место)
  game-awards.js     — начисление XP и золота из sessions[]
  storage/           — схема, IndexedDB, сессии, события, миграция, экспорт и импорт; storage/test.html — ручной стенд
  vendor/pdfjs/      — pdf.js 3.11.174
  icons/, manifest.webmanifest
  build-dist.sh      — сборка dist/ для GitHub Pages
  smoke-*.html       — быстрые проверки сессий и экспорта
  MVP.md, STORAGE.md, READER.md — техническая документация
  test/
    metrics.py         — метрики теста по экспортам
    android-verify.mjs — автотест читалки текста (Pixel 7, headless Chrome)
    pdf-verify.mjs     — автотест PDF-читалки (критерий приёмки)
    PDF-PROGRESS.md    — рабочая заметка Фронта о ходе PDF-исправления
    fixtures/          — gen.py (генерирует тестовые PDF), package.json (puppeteer-core, pngjs), «Длинная книга.txt»
```

**Про автотесты.** `android-verify.mjs` и `pdf-verify.mjs` написаны под старый компьютер и ищут файлы по путям `/workspace/rqtest/...` и `/workspace/readquest/...`. Им нужны Google Chrome, `npm i` из `fixtures/package.json` и тестовые PDF, которые создаёт `fixtures/gen.py` (reportlab, pikepdf, Pillow). Сайт должен раздаваться локально по адресу `http://127.0.0.1:8766/readquest/`. Пути можно переопределить переменными `RQ_URL`, `RQ_OUT`, `RQ_PDFDIR`, а путь к текстовой книге и выходную папку в `gen.py` придётся поправить руками.

**Не перенесено:** скриншоты проверок (`shots/`), зеркало старой версии (`mirror/`), собранная `dist/` (она и так в `main`), отладочные скрипты и экспорты с тестового компьютера.
