## 1. Продукт

ReadQuest — читалка с геймификацией: читаешь свои книги и получаешь опыт, золото и награды.

**Откуда начали.** Прототип v6 — один HTML-файл примерно на 3600 строк (`source/v6.html`): библиотека, читалка, RPG-профиль, XP и стрики, квесты, магазин, цитаты, ачивки, поддержка PDF и FB2. Этот файл больше не правим, он остаётся как образец.

**Для кого.** Взрослые 20–35 лет, которые раньше много читали, а сейчас читают реже двух раз в неделю, и у которых есть хотя бы один свой файл книги.

**Главная метрика.** Сколько дней в неделю человек читает не меньше 10 минут. Цель: медиана ≥ 4 дней на второй неделе теста.
- Мягкий стрик засчитывается с 2 минут в день.
- Ежедневное задание и метрика засчитываются с 10 минут в день.

### MVP — 4 экрана

Рабочий файл приложения — `source/app.html`. Нижняя навигация: **Библиотека | Профиль**. Читалка и итог сессии вкладками не являются.

| Экран | Что на нём |
|---|---|
| Библиотека | «Продолжить», цель 10 минут, мягкий стрик, полка книг. Без RPG. |
| Читалка | Режим фокуса включён по умолчанию: никаких всплывающих XP и RPG. Таймера и кнопки ▶ нет: открыл книгу — минуты считаются. Внизу тонкая полоска прогресса дня (3 px), над ней справа номер страницы «34 / 210». Щипок двумя пальцами меняет размер шрифта (14–30), во время жеста видна плашка «Aa N», текст перестраивается один раз после отпускания. |
| Итог сессии | XP, стрик, прогресс ежедневки и недели. Строки «+30 🪙 ежедневка выполнена» / «+120 🪙 неделя выполнена», только если начислено этой сессией. Одна кнопка «В библиотеку». |
| Профиль | Рамка героя и кнопка-заглушка «Создать героя», статус ежедневки и недели (без кнопок «Забрать»), золото, шторка «Награды из жизни». |

Всё остальное из v6 (цитаты, словарь, игровой магазин, список квестов, статистика, календарь, ачивки, босс, питомец, таланты, снаряжение и т. д.) спрятано за флагом `mvp`. По умолчанию `mvp = true`. Переключатель: **Настройки → MVP**. Если выключить, вернётся полный интерфейс v6.

### Экономика

- **Опыт (XP)** = 10 × засчитанные минуты, только за чтение. Считается из строки в `sessions[]`, по одному разу на сессию.
- **Золото** — только за задания:
  - ежедневка +30 🪙: день, в котором набралось 10 минут;
  - неделя +120 🪙: на 4-й засчитанный день недели пн–вс. 5-й день недельную награду второй раз не даёт.
- Награды начисляются **автоматически на экране итога сессии**, кнопки «Забрать» нет.
- Начисление идемпотентно: XP — по UUID сессии (`game.awardedSessionIds`), ежедневка — по дню (`game.dailyPaidDays`), неделя — по понедельнику недели (`game.weeklyPaidWeeks`). Повторный показ итога, перезагрузка или повторный импорт бэкапа второй раз не платят.
- **«Награды из жизни»** (например, «Кофе», «Серия сериала»): цены по уровням 100 / 250 / 500 🪙, своей цены нет. По умолчанию 3 слота, можно до 5.
- **Защита от забытой книги:** не больше 3 минут на одну страницу (настройка «Макс. время на страницу» = 3 мин по умолчанию). Фон и скрытая вкладка = 0.
  - Для PDF потолок может расти: если человек зумит или двигает страницу больше чем на 20 % экрана, к потолку этой страницы добавляется +1 минута, не чаще раза в минуту и не выше 8 минут. На новой странице снова 3 минуты.
- **День — локальный** (по часам телефона, не UTC). Сессия относится к дню, в который началась: чтение 23:50–00:15 — одна строка, все минуты идут в первый день.

### ИИ-герой — отложен

Сейчас есть только кнопка-заглушка «Создать героя». Она показывает «Скоро ✨» и записывает событие `hero_create_tapped`. Настоящий ИИ-портрет делаем, только если на неё нажмёт больше трети тестеров.

Если будем делать:
- нужен тонкий прокси-сервер `POST /avatar`, потому что ключ API нельзя класть в HTML;
- предварительные цены: первый портрет бесплатно, перегенерация 80 🪙, слот скина 60 🪙, редкий образ 200 🪙.

## 2. Данные

Подробно — в `source/STORAGE.md`. Схема `schemaVersion: 1`.

- **LocalStorage**, ключ `rq_v1`: `{ schemaVersion: 1, progress, game, library }`. Тела книг сюда не кладём. Настройки читалки — в ключе `rq_set`.
- **IndexedDB** `readquest` (версия 3), хранилища:
  - `files` — тела книг (`text:{id}`, `pdf:{id}`);
  - `sessions` — `sessions[]`;
  - `events` — события.
- **`sessions[]`** — только чтение, одна строка на сессию:
  `{ id: UUID, date: 'YYYY-MM-DD', bookId, minutes, pageTurns }`.
  `id` генерирует читалка (`crypto.randomUUID()`), а не автоинкремент базы. Старые строки без `id` получают детерминированный `legacy-…` id. Минуты считает только `reader-session.js` в конце сессии.
- **`events`** — `page_visible` с `pageVisibleMs` и аналитика (`hero_create_tapped`). В `sessions[]` они не попадают.
- **`game`**: `gold`, `awardedSessionIds`, `dailyPaidDays`, `weeklyPaidWeeks`, `rewardPurchases[{ id, title, price, at }]`, `anti: { minSec: 12, maxMin: 3 }`.
  Старые поля `dailyClaimed` / `weeklyClaimed` остались для совместимости: их один раз читает миграция, а новые сборки их больше не пишут.
- **Стрик** лежит в `progress.streak`, не в `game`.
- **Экспорт и импорт** — один JSON:
  `{ schemaVersion: 1, progress, game, library, sessions, events, settings? }`. Файлы PDF в него не входят. При импорте `sessions` и `events` заменяются целиком.
- Миграция со старого v6 (ключ `readquest`) в `rq_v1` выполняется один раз при запуске.
- Если приложение закрыли без «←», открытая сессия сохраняется черновиком (`rq_session_draft`) и записывается при следующем запуске.

## 3. Хостинг и выкладка

- GitHub Pages раздаёт сайт из ветки `main` (корень): https://hachirovmagomed-glitch.github.io/readquest/
- В `main` лежит **только собранная `dist/`** плюс пустой файл `.nojekyll` (его не удалять), исходников там нет.
- pdf.js 3.11.174 (лицензия Apache-2.0) лежит в `source/vendor/pdfjs/`, CDN во время работы не используется.

Как выложить новую сборку:

```bash
git clone https://github.com/hachirovmagomed-glitch/readquest.git
cd readquest && git checkout project
cd source && ./build-dist.sh          # соберёт source/dist/, номер сборки = дата-время (или RQ_BUILD=...)
# дальше — содержимое dist/ в корень ветки main:
cd .. && git worktree add ../rq-main main
find ../rq-main -mindepth 1 -maxdepth 1 ! -name .git ! -name .nojekyll -exec rm -rf {} +   # .nojekyll оставить!
cp -a source/dist/. ../rq-main/
cd ../rq-main && git add -A && git commit -m "Build <номер>" && git push origin main
```

- Номер сборки виден в приложении: **Настройки → Данные**. Через 1–2 минуты после push проверь, что на сайте новая сборка.
- Локальный просмотр: `cd source && python3 -m http.server 8765` и открыть `http://localhost:8765/app.html`.
- После выкладки обнови `source/` в ветке `project`, чтобы исходники совпадали с сайтом.

## 4. План теста

1. **Мини-проверка** силами команды, 2–3 дня.
2. **Тест на 10–20 людях**, 2 недели.
3. **5 интервью** в конце.

Метрики считаются по экспортам (Настройки → экспорт JSON), по одному файлу на тестера:

```bash
cd source/test
python3 metrics.py --start YYYY-MM-DD exports/*.json
```

Скрипт выводит:
- медиану дней ≥ 10 минут на 2-й неделе (цель ≥ 4);
- долю вернувшихся на 2-й неделе (тревога, если меньше 50 %);
- долю «пустых» сессий с минутами, но без перелистываний (тревога, если больше 10 %);
- долю нажавших «Создать героя» (больше 33 % — делаем ИИ-героя);
- долю купивших хотя бы одну «награду из жизни».

**Перед мини-проверкой** очистить данные сайта в Chrome на телефоне: Настройки сайта → Хранилище → Очистить. Тогда в экспорте не останется старых записей.

Дни, когда на телефоне был баг с пропадающим текстом, в мини-проверку не идут. Отсчёт 2–3 дней начинается заново после того, как пользователь пройдёт проверку на своём Android.

**PDF-БЛОКЕР (исправлен в `20261006-1537`, ждёт проверки на реальном Android)** (книга пользователя: Фишер, «Капиталистический реализм», 144 стр.):

2. Сломанная матрица страницы: она схлопывается в крошечную строку или рисуется перевёрнутой на 180°.
3. При зуме и пане текст и бежевая подложка страницы разъезжаются, буквы по краям обрезаются.
4. Ползунок отстаёт на 1 от напечатанного номера (печатная 76 → ползунок 75/144).

**Критерий приёмки:** 10 перелистываний, щипок туда и обратно, пан и два входа в полноэкранный режим подряд. Ни одного пустого кадра, ни одного перевёрнутого, ни одного, где текст и подложка разъехались.

**Состояние исправления PDF** (подробно — `source/READER.md`, раздел «PDF reader, build 5»; автотест — `source/test/pdf-verify.mjs`). Фикс **выложен в `main`** сборкой `20261006-1537`.
- Что сделано в коде:
  - один родитель трансформации для подложки, холста и текстового слоя; во время жеста — только CSS-transform, после отпускания — перерисовка в высоком разрешении (не больше 16 Мп);
  - двойная буферизация: каждый рендер идёт в новый холст вне DOM и подменяет видимый только после завершения; прошлый рендер отменяется, повторы при ошибке и сторож от «потерянного» листания;
  - поворот только из самого файла (`page.rotate`);
  - перерисовка после изменения размера и полноэкранного режима ждёт, пока размер устоится, и никогда не идёт при размере 0;
  - номера страниц и ползунок берутся из меток самого PDF (`getPageLabels()`), например «76 / 144»; при перетаскивании ползунок показывает метку целевой страницы;
  - pdf.js лежит в `vendor/pdfjs/`, без CDN;
  - минуты для PDF считает тот же `reader-session.js` через события `pageShown` / `pageTurned` / `userActive`. Потолок на страницу 3 мин; в PDF +1 мин за пан больше 20 % экрана или смену зума, не чаще раза в 60 с, не выше 8 мин. Для текста 3 мин.
- Причины багов (воспроизведены на старой сборке `1306` в эмуляции Pixel 7, все четыре):
  1. пустой кадр: старый код очищал видимый холст (`canvas.width=…`) перед каждым асинхронным рендером, а pdf.js рисует постепенно;
  2. крошечная или перевёрнутая страница: второй рендер в тот же холст, пока первый не закончился. Сброс размера холста сбрасывал матрицу, остаток первого рендера рисовался без матрицы вьюпорта (мелко и без переворота по y), а второй pdf.js отклонял. Это не `/Rotate`;
  3. обрезание при зуме: щипок масштабировал страницу от `50% 0` внутри прокручиваемой обёртки, левая часть уходила в недоступную зону; пан был нативной прокруткой обёртки, поэтому подложка и холст разъезжались;
  4. «+1»: старая сборка показывала номер файла (79/144 на печатной 76), меток PDF не читала.
- Последний прогон в эмуляции (Pixel 7, headless Chrome, часть проверок с CPU ×6), сборка `20261006-1537`: **`pdf-verify.mjs` — 35/35, `android-verify.mjs` — 71/71.**
- Оговорки:
  - в headless Chrome полноэкранный режим не меняет размер окна, поэтому вход и выход из него эмулируются сменой размера вьюпорта;
  - реальных ограничений памяти GPU и холста на Android эмуляция не даёт, потолок 16 Мп выбран с запасом;
  - в одном из предыдущих прогонов при CPU ×6 одно листание из десяти пропало. Добавлены повтор рендера и сторож, в финальном прогоне чисто, но на телефоне стоит посмотреть отдельно;
  - нужна проверка на реальном Android (ниже).

**Проверка на реальном Android** (делает пользователь на новой сборке, когда она выйдет):
1. В Настройки → Данные стоит новая сборка.

    android-verify.mjs — автотест читалки текста (Pixel 7, headless Chrome)
    pdf-verify.mjs     — автотест PDF-читалки (критерий приёмки)

**Про автотесты.** `android-verify.mjs` и `pdf-verify.mjs` написаны под старый компьютер и ищут файлы по путям `/workspace/rqtest/...` и `/workspace/readquest/...`. Им нужны Google Chrome, `npm i` из `fixtures/package.json` и тестовые PDF, которые создаёт `fixtures/gen.py` (reportlab, pikepdf, Pillow). Сайт должен раздаваться локально по адресу `http://127.0.0.1:8766/readquest/`. Пути можно переопределить переменными `RQ_URL`, `RQ_OUT`, `RQ_PDFDIR`, а путь к текстовой книге и выходную папку в `gen.py` придётся поправить руками.

**Не перенесено:** скриншоты проверок (`shots/`), зеркало старой версии (`mirror/`), собранная `dist/` (она и так в `main`), отладочные скрипты и экспорты с тестового компьютера.
